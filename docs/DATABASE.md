# Database

## Base tables

`rooms`, `room_users`, `player_inventory`, `room_players`, `live_auction_state`, `user_squads`, `bid_history` were created from [archive/DATABASE_SETUP.md](archive/DATABASE_SETUP.md) and extended by later files. That guide's table definitions predate several columns (squad sizes, `purchased_at`, `auto_hammer`, `ready_to_start`, `is_paused`); the files below add them.

## Apply order

`npm run db:apply` runs these in one transaction (`-- --dry` rolls back):

| # | File | Adds |
|---|---|---|
| 1 | `player_inventory_add_team.sql` | `player_inventory.team` |
| 2 | `consensus_and_lobby.sql` | ready flag, `list_joinable_rooms` |
| 3 | `auction_manual_and_filters.sql` | `auction_start_first_lot`, `auction_hammer_advance`, host filters, `_auction_is_room_admin` |
| 4 | `restart_room_auction.sql` | `restart_room_auction` |
| 5 | `auction_pause.sql` | pause / resume |
| 6 | `auction_bid_slabs.sql` | squad sizes, slab-only `place_auction_bid`, purse lock |
| 7 | `squad_visibility.sql` | `user_squads.purchased_at`, members can read all squads |
| 8 | `security_hardening.sql` | locked-down RLS, `join_room`, guarded `initialize_room_players` |
| 9 | `auto_hammer.sql` | optional server-side auto-sell |
| 10 | `undo_last_sale.sql` | host "Undo last sale" |
| 11 | `indexes.sql` | indexes for RLS and lot queries |
| 12 | `pause_close_away.sql` | pause reasons, host Close with message, away auto-pause heartbeat |
| 13 | `cohost.sql` | co-hosts and host transfer |
| 14 | `cleanup_rooms.sql` | `cleanup_stale_rooms` (maintenance, not callable from the browser) |
| 15 | `auction_sets.sql` | lot order "by sets"; redefines `auction_pick_next_lot` |

Order matters because files 3 and 5 also define `place_auction_bid`; file 6 must be its last definition. Files 3, 5 and 9 define `auction_hammer_advance`; file 9 is the last. File 15 also redefines `auction_pick_next_lot` (also in file 3) and must stay after it. Do not run an earlier file alone against a live database.

Not in the runner: `FIX_READY_BUTTON.sql` (one-off realtime publication fix), `place_auction_bid.sql` and `finalize_auction_timer.sql` (superseded, reference only), `player_inventory_ipl2026_seed.generated.sql` (data seed, generated by `npm run import:ipl2026`).

## Environments

Production is the only database today. Prefer a second Supabase project for staging and point `SUPABASE_DB_URL` at it while testing schema changes.

## Testing database rules

`place_auction_bid` and the host functions need a signed-in user (`auth.uid()`). `npm run db:test` runs the rule tests in `scripts/db-tests/` (139 checks: bid rules, security attacks, auto-sell, undo, pause and close, co-hosts, cleanup, sets). Each file runs in a single transaction that inserts temporary `auth.users`, sets `request.jwt.claim.sub` to act as them, and always rolls back, so nothing persists. They read `SUPABASE_DB_URL`; point it at staging. They are not part of CI because CI has no database secret.
